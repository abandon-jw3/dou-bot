# 框架介绍

dou-bot 帮你用 TypeScript 编写 QQ 官方机器人的群聊和私聊功能。把处理函数标记为命令，就能接收用户输入并回复；需要更多功能时，可以加入参数校验、权限限制、按钮和多轮对话。

## 从你想做的功能开始

接收用户图片、视频或文档，先看 [附件与自动上传](./attachments.md)；读取当前发送者、群和角色，先看 [身份参数](./identity.md)。两者都有可运行的完整示例。

| 你想做什么             | 从哪里开始                                  |
| ---------------------- | ------------------------------------------- |
| 让机器人回复第一条消息 | [快速开始](./quick-start.md)                |
| 接收城市、数量等参数   | [命令参数](./parameters.md)                 |
| 限制谁能使用某个命令   | [访问限制](./access.md)                     |
| 发送图片或可点击的菜单 | [消息](./messages.md)、[按钮](./buttons.md) |
| 逐步询问并收集用户输入 | [多轮对话](./prompts.md)                    |
| 不连接 QQ 就测试业务   | [离线测试](./testing.md)                    |

## 适用范围

- QQ 官方群聊、私聊，以及对应的消息和按钮事件。
- 每个应用实例选择 WS 或 Webhook 接入。
- Node.js、ESM、传统 TypeScript 参数装饰器；本手册统一使用 TypeScript 5.9.3。
- 进程内队列、去重、冷却和 prompt。重启后这些状态会重置。

不包含 QQ 频道业务、Koishi 插件兼容或运行时热更新。业务数据库、定时任务和外部服务由应用自己选择、注入与管理。

## 一条消息怎样被处理

QQ 投递事件后，框架识别会话与命令，依次执行模块、类和方法的 Guard，再绑定参数、占用冷却，最后调用处理器。命令返回字符串或消息对象时自动回复。

原始 `@On()` 观察器独立执行。被 prompt 消费的回答属于已有对话，不会作为新命令再跑一遍 Guard。

## 需要准备什么

你需要能使用 npm 和基础 TypeScript。如果准备连接 QQ，还需要在 QQ 机器人平台取得自己的 AppID、AppSecret，并确认机器人具备对应群聊或私聊能力。先看 [快速开始](./quick-start.md)；没有凭证时可以用 [离线测试](./testing.md)。

## 选择接入方式

第一次使用可以从默认的 [WebSocket](./ws.md) 开始：让程序保持运行即可，不需要公网回调地址。已有 HTTPS 服务、希望通过 HTTP 接收事件时，可以选择 [Webhook](./webhook.md)。两种方式使用相同的业务模块。

## 使用哪个版本

本手册适用于 **dou-bot 0.7.0**。按照快速开始安装这个版本，即可使用文中的 API 和示例。升级前查看 [更新日志](../changelog.md)。

消息类型、普通群消息投递和主动发送权限由你的 QQ 机器人账号决定。首次连接后，先试一条私聊命令和一条群聊命令；没有回复时按 [排错指南](./troubleshooting.md) 检查。Webhook 的接入准备和当前限制见 [Webhook 指南](./webhook.md)。
