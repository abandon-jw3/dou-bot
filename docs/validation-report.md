## 0.2.0 参数增强验证

- 两种核心词序、包含两个补充词的全部 24 种排列，分别经群聊与私聊测试入口验证；Rest 放在方法参数首位仍最后收集。

- help/帮助 按导入启用，应用前缀与目录隔离，别名合并；独立安装包消费者实际运行新 API。
- 输入错误回复默认关闭；开启后只展示框架解析错误和用法，不回显非法原文或内部异常。重复投递抑制、回复序号、发送失败去重、匹配器抛错/误返回 Promise 均验证。

## 实机发现及修复

1. WS 升级请求需要携带 Authorization / X-Union-Appid。已与参考适配器底层 HTTP 实现对照，并通过真实 READY；网关查询缓存 60 秒，避免每次重连都请求 /gateway。
2. GROUP_MESSAGE_CREATE 可能在 content 中保留 <@openid>。归一化仅移除开头与本事件 mentions[].is_you === true 精确匹配的自身提及；保留其他身份、参数内提及及 raw。依据包含实际接收、发送结果和用户确认。
3. 按钮省略 visited_label 时，实测点击后文案消失。默认填入原 label，显式 visitedLabel 继续生效；群聊和私聊复测均通过。

前缀配置支持单一字符串：默认 /，也可使用 !、bot: 或空字符串。空前缀替换默认 /；按首个完整指令名匹配，不在普通正文中搜索关键词。群聊和私聊使用相同配置。

## 本轮核心修复与验证

- token 与媒体有效期只接受合法数字或十进制字符串，拒绝布尔值、数组、非有限值及溢出。token 按请求开始时间保守计算期限；迟到或已失效的新响应不能替换仍有效的旧凭证。
- 内部 Clock 管理单调时间、墙上时间和计时器。提前刷新、指数退避、活跃去重保护、完成后 TTL、回复作用域保留和取消均有可控时间测试。
- API 调用等待共享 token 和读取 HTTP body 共用一个超时预算；单个调用者取消不会终止其他调用者的共享刷新。Content-Length 已知超限也会取消尚未读取的响应流。
- WS 成功 READY/RESUMED 后重置退避；不响应 close 的 socket 到期限会 terminate；停止后不重连，迟到帧不再进入业务。
- Webhook 中途断开请求的后续 error 不会成为未处理异常；读取名额释放，独立模式在关闭期限内回收自有 HTTP 连接，嵌入模式不关闭宿主 server。
- OperationLedger 只保留已接纳操作；超过操作数上限不分配回复序号或发请求。错误去重记录也有界。
- 错误回调超时后禁用，关闭会撤销回调计时器；异常 getter、无法字符串化的抛出值和 logger 抛错不会反过来破坏处理流程。错误名、字符串错误码、traceId 与字段名经过凭证脱敏。
- 独立打包检查发现并修复过私有 SocketFactory 类型外泄；公开 BotFactory 使用独立声明入口，用户无需额外安装 @types/ws。
- 同一组群/私文本、图片、Markdown 和回调事件经真实本机 WS 与 Webhook HTTP 输入，业务调用、发送路径和消息负载一致。

基线脚本只使用合成事件与模拟 HTTP Response，不连接 QQ。每种负载预热 200 次、串行执行 5000 次；默认缓存保留状态，RSS 包含 Node 与同一进程中的前序负载。测量时间为 2026-09-29，原始结果见 performance-baseline.json。
