# Windows 部署

先完成 [快速开始](./quick-start.md) 并确认机器人能在本机正常收发。这里使用已验证的 Node.js 24.21.0、npm 11.19.0 和 TypeScript 5.9.3。

## 部署内容

保留源码或已构建的 dist、package.json、package-lock.json 以及你自己的本地环境配置。提交锁文件；真实 .env 不提交到 Git。初次部署执行 npm ci，再执行构建命令。

```sh
npm ci
npm run build
npm start
```

上面的脚本来自 [项目结构](./project.md)。文档仓库的演示入口使用不同路径，见 [完整示例](../examples/hello.md)。

## 运行与退出

前台运行便于第一次观察启动与错误输出。需要长期运行时，可用你熟悉的 Windows 服务或任务管理方式托管 Node，但要明确工作目录、环境文件路径、重启策略和退出期限。

保留 SIGINT/SIGTERM 到 app.close 的关闭逻辑。重复启动同一机器人的 WS 实例可能产生连接干扰；更新时先停止旧进程，再启动新进程。SDK 关闭后不能重启同一应用对象。

## 观测状态

使用 app.status 或 app.snapshot 查看运行、重连、队列及等待中的 prompt；用 logger/onError 记录错误码、阶段和必要业务信息。不要把“进程还在”作为机器人已成功连接的唯一判断。

截图、日志、抓包中可能带有用户消息或身份信息，对外分享前应按实际内容处理。原始事件不适合作为默认日志字段。

## Webhook 部署额外要求

提供 QQ 能访问的 HTTPS 回调地址，代理到 SDK 的 HTTP 端口，保持请求原文与签名头。默认 host 为 127.0.0.1；开放到其他地址前确认自己的网络边界。步骤与验收限制见 [Webhook](./webhook.md)。

## 升级与回退

升级时指定明确的 npm 版本，阅读更新日志，重新安装、编译并运行业务测试。保留上一版锁文件和构建产物，以便回退；回退代码不会自动恢复进程内的 prompt、冷却、队列或去重状态。

WS、Webhook 均不提供跨进程恰好一次保证。需要持久化一致性的业务应自己实现存储与幂等检查。
