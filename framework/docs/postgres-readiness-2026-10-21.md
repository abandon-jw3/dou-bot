# PostgreSQL 与慢接口专项验收（2026-10-21）

**发现并修复三处连接生命周期问题；两版 Node 的数据库专项均为 16/16 通过。** 这是故障回归和有界处理链路验收，尚未完成真实 SQL 固定速率容量测试或长期生产观察。

## 范围

- 基于 main / c654be3 及已有未提交改动；本轮 SDK 源码指纹为 `efbd2880a235c874e078728023b9b3bb7f0286d94af2c49811e1c0e7fb0c10e7`。版本仍为 0.8.0，契约仍为未发布的 2.0；没有修改依赖或公开 API。
- 目标服务器使用独立 PostgreSQL 17.6 临时容器：0.5 核、256 MiB、无额外 swap、新建 tmpfs 数据目录，仅监听本机随机端口。未使用既有数据库或 framework/.env，也未复用旧 TEST_DATABASE_*。
- 每个用例使用随机测试 schema。断连仅针对该用例拥有的连接；迁移用例通过自己持有的随机 schema 锁识别阻塞连接。
- SDK 在服务器上运行，连接真实 PostgreSQL 和本机 HTTP 慢接口；QQ 请求使用测试夹具，事件直接进入执行器。未连接真实 QQ，也没有经过 WS/Webhook/Nginx。
- SDK 进程没有沿用此前容量测试的 CPU 配额；本轮耗时不能与此前 500/s 结果比较。

## 已修复问题

| 问题                        | 实际复现                                             | 修复                                                                           |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| 事务等待业务代码时断连      | 借出的连接发出未捕获异常，事务回调尚未结束           | 监听连接错误，保留首次错误，在回调结束后拒绝；不重试业务回调                   |
| 迁移等待数据库锁时断连      | 查询拒绝后仍产生未捕获连接异常                       | 迁移期间接管连接错误，并丢弃故障连接                                           |
| 关闭期限到达时 SQL 仍在执行 | 框架与 pg 查询回调先后归还同一连接，触发重复归还异常 | 先断开连接，让查询回调归还，再回收仍被借用的连接；同时覆盖关闭前已经断连的情况 |

修复不改变连接池默认值、事务提交/回滚规则或自动重试策略。手动借出的连接仍应由业务归还；框架只在关闭超期后执行强制清理。

初次故障测试为 3/5 通过；两项失败分别对应事务断连和强制关闭。补充迁移及处理链路后的中间版本为 14/15 通过，迁移断连失败。上述失败日志与编译产物均保留，没有改写为成功结果。

## 处理链路

- 两个合成账号，每个账号有独立的 2,000 个群 OpenID，共 4,000 条地址记录。
- 冷、热两轮各 4,000 条命令；共完成 8,000 条，额外 80 次重复投递全部去重。
- 中间件从共享数据库查询，再访问 HTTP；两个 ContextValue 参数共用一次加载。共 8,000 次加载，其中 400 次慢接口请求为 80 ms，其余为 2 ms。
- Guard/参数等原有行为由完整 SDK 回归覆盖；本链路另核对群路由、发送账号、用户数据、单次回复和关闭清理。
- 测试端最多 24 条在途命令，执行并发 16、出站并发 8、连接池上限 4。执行完一条才补下一条，属于闭环负载，不验证恒定到达率下的接纳能力。

| Node    | 冷轮耗时 | 热轮耗时 | 完成命令 | 连接峰值 / 等待峰值 | 关闭后连接 |
| ------- | -------: | -------: | -------: | ------------------: | ---------: |
| 24.0.0  | 9,225 ms | 7,755 ms |    8,000 |              4 / 12 |          0 |
| 24.21.0 | 9,535 ms | 6,698 ms |    8,000 |              4 / 12 |          0 |

这些耗时来自同一批回归中运行的用例，每版仅一轮，不用于比较 Node 性能或推导吞吐上限。两轮均无非预期业务错误、跨账号回复或重复执行。
