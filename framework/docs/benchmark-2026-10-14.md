# 本机框架 Benchmark：2026-10-14

环境：Apple M4、10 核、32 GiB 内存，macOS ARM64，Node.js 24.21.0，TypeScript 5.9.3。基线提交 `07d2c3e`，工作区开始时干净，SDK 源码与 v0.8.0 相同。

本轮测量执行器接纳、路由、参数、中间件和模拟回复。单进程串行投递合成私聊事件，使用内存 HTTP 响应，没有连接 QQ、数据库或测试服务器；不包含 WS/Webhook 传输与验签。

## 吞吐与延迟

吞吐为两个独立进程、各五轮的合并中位数。延迟由另一进程逐条计时，共五轮；表中 P95/P99 来自每种场景全部样本，单位为微秒（1 ms = 1,000 µs）。

| 场景                            | 吞吐中位数（次/秒） | P95（µs） | P99（µs） |
| ------------------------------- | ------------------: | --------: | --------: |
| 无参数、不回复                  |             129,209 |    10.000 |    13.958 |
| 文本回复                        |              44,316 |    28.625 |    39.625 |
| 严格参数与 normalize            |             114,515 |    11.958 |    16.917 |
| 513 项枚举匹配                  |             110,540 |    11.125 |    15.708 |
| 中间件懒加载、两次注入          |              60,813 |    20.625 |    30.834 |
| 注册但不读取上下文              |              90,161 |    14.959 |    21.208 |
| 64 KiB 图片编码、模拟上传与发送 |               8,211 |   149.292 |   194.834 |

- 缓存满后的拒绝速度另测为 **671,546 次/秒**，这是拒绝处理指标。
- 吞吐阶段保留 80 组测量，共 325,000 次操作，其中 20,000 次为预期拒绝；预热不计入吞吐。
- 延迟阶段保留 162,500 条逐事件耗时。计时调用与数组写入会增加测量开销，因此不使用这一阶段计算主表吞吐。
- 事件处理、回复、上传、数据加载次数均通过断言；没有选择性丢弃慢样本。逐轮范围及原始统计见 [JSON 报告](benchmark-2026-10-14.json)。

## 内存

追加每种场景各一个独立进程，避免将连续混合测试的累计进程内存归到单一场景。下表为业务处理完毕、应用仍开启时的 GC 后快照：

| 场景           | 保留的消息记录数 | JavaScript 堆（MiB） | 进程 RSS（MiB） |
| -------------- | ---------------: | -------------------: | --------------: |
| 无参数、不回复 |            5,500 |                11.92 |           92.50 |
| 文本回复       |            5,500 |                16.06 |          176.38 |
| 中间件懒加载   |            5,500 |                12.27 |          139.14 |
| 64 KiB 图片    |              600 |                10.70 |          100.95 |
| 缓存满后拒绝   |           10,000 |                14.65 |           95.62 |

- 上述数量同时对应去重与回复记录。图片场景为 100 次预热、500 次测量，其他普通场景为 500 次预热、5,000 次测量。
- 关闭后，公开快照的队列、事件保留字节、prompt、去重和回复缓存全部归零。独立进程再空闲 100 ms 并 GC，堆占用为 **8.90～10.04 MiB**。
- 连续混合吞吐测试的计时阶段最高采样 RSS 为 **403.67 MiB**。独立场景的 GC 后 RSS 为 **92.50～176.38 MiB**；关闭后 RSS 没有随堆同步回落。
- RSS 包含 Node、测试夹具及进程保留内存；未做原生内存归因，不能把它当作 SDK 净占用。短时快照不能证明长期无泄漏。

## 复测与记录

标准吞吐测量在 framework 目录执行：

```sh
npm run benchmark:framework -- 5 local-a
npm run benchmark:framework -- 5 local-b
```

- 两次命令顺序执行，保留两个报告；比较时固定 Node、主机、脚本与容量配置。
- 本轮标准测量程序与 2026-10-11 的已编译程序 SHA-256 相同。历史报告使用较早 SDK 源码，未进行同时段 A/B，不据此宣称性能提升或退化。
- 本轮运行目录：`framework/work/benchmark-runs/2026-10-14-2a504b/`。包含环境、逐轮 JSON、48 份逐事件数据、诊断程序生成脚本及 `benchmark-evidence-2026-10-14.zip`。
- 运行目录被 Git 忽略，需要时单独迁移；[JSON 报告](benchmark-2026-10-14.json)保存逐轮统计、源码及测量程序指纹。
- 未控制后台应用负载、CPU 亲和性和文件系统缓存；未进行并发业务、2,000 群或多日测试。此结果不表示真实 QQ 平台吞吐或部署容量。
