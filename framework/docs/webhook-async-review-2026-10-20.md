# Webhook 异步验签与服务器复验（2026-10-20）

**异步验签已有改善，当前资源配额下仍未验证稳定 500/s。** 500/s 的短测曾全部接纳，但 5 分钟复验仅接纳并完成 147,249 / 150,000 条，末段积压再次接近上限。400/s 的 5 分钟结果为通过；这不是框架在所有部署下的吞吐上限。

## 实现

- 使用 Node 内置异步验签，密钥继续缓存；没有新增运行依赖或调整默认执行、出站并发。
- 原始字节、签名格式、AppID、时间戳与挑战校验保留。验签完成后再次检查时间戳及关闭状态。
- 新增账号级 `transport.verifyTimeoutMs`，默认 10 秒；超时返回 503。正文读取超时仍由 `readTimeoutMs` 控制，返回 408。
- 断线或超时后，底层验签仍占用 `maxConcurrentRequests` 名额，直到实际完成。迟到结果不会接纳消息；关闭等待受现有统一期限约束。
- Node 的原生任务不能通过取消 Promise 强制终止；异步验签共用线程池。API 依据见 [Node 24.21 文档](https://nodejs.org/download/release/v24.21.0/docs/api/crypto.html#cryptoverifyalgorithm-data-key-signature-callback)，实际行为由两版 Node 测试验证。

## 同机对照

- 2 vCPU / 约 1.92 GiB 服务器；SDK、模拟 API、监督进程共享 **1.5 核 / 1 GiB**，无 swap。发压端在本机，SSH 开销另计。
- 同一混合业务、同一工具指纹；同步基线和异步候选分别保存源码。HTTP 请求上限均为 256；表中并发表示入站执行/出站。
- 单账号、2,000 个合成群标识；每轮先 10 秒 200/s 预热，测量后 15 秒 200/s 恢复，再排空。保留内存状态窗口与原容量判定。
- 不连接真实 QQ/SQL，不经过 Nginx/TLS，不包含图片渲染。未设置 `UV_THREADPOOL_SIZE`，没有改变服务器 CPU 配额。

- 六轮完整性均通过，发压漏发为 0。接纳包含模拟重试后成功的唯一首次事件；不能据此声称首投均成功。
- 成功延迟从发压端计划时刻计算，包含连接、SSH 和处理等待。完成计数还包含预设的权限拒绝、输入错误和业务异常；可能在恢复期完成，不能将完成数直接除以窗口时长当作稳定吞吐。
- 异步版 128/32 的 120 秒样本 P95 为 2.427 秒，同配置同步样本为 14.141 秒；更长的 500/s 复验暴露了后段积压。各配置/时长只有单轮样本，不能把差值当作保证。
- 总 CPU 消耗没有因异步而消失，测试组仍有配额限流。完整 CPU、内存、时钟、重试和清理数据见 [JSON](webhook-async-review-2026-10-20.json)。

## 回归与交付

- 两版 Node 各 358 项测试：356 通过、2 项专用数据库测试跳过；新增 11 项验签、取消与关闭回归。
- 原始字节、非法签名、过期时间戳、重复请求头、挑战、过载连接复用、多账号及 WS/Webhook 协议对照通过；358 项覆盖率运行通过，整体行覆盖率 **96.79%**。
- 170 个公开导出、128 组类型契约和当前 tarball 消费者通过。新增消费者的一处类型标注问题已修正并复验，失败日志保留。
- 用法见 [多机器人指南](multi-bot.md#webhook-请求限制)。源码契约仍为 2.0、SDK 版本仍为 0.8.0；新配置尚未发布，example、website、技能保持 npm 0.8.0。
- 本轮测试单元、监控和 SSH 转发已清理；Nginx 与 PostgreSQL 未改动，证据和独立测试目录保留。未提交、推送、发布或部署真实服务。

## 接续方向
