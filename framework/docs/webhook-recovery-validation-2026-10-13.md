# 0.8.0 Webhook 故障与恢复实测

日期：2026-10-13（Asia/Shanghai）。使用 npm 的 dou-bot 0.8.0，在既有公网 HTTPS 入口继续验证。SDK 源码和依赖未修改。完整时间、计数、快照和程序指纹见 [结构化记录](webhook-recovery-validation-2026-10-13.json)。基础功能验收见 [前一轮记录](webhook-validation-2026-10-13.md)。

## 本轮实测结果

| 场景       | 操作与观察                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| HTTP 503   | 私聊、群聊首次回调各返回一次 503，不交给 SDK；同一消息分别在约 4.50 秒、4.34 秒后再次由平台投递，处理器各执行一次并回复。用户确认两边收到。                              |
| 延迟响应   | 首次回调计划延迟 20 秒，Nginx 读取超时临时设为 45 秒。私聊、群聊连接分别在约 3.00 秒、2.81 秒被对端关闭；首投后约 7.91 秒、7.75 秒收到同一消息重投，回复成功，用户确认。 |
| 进程内去重 | 两条真实 QQ 事件各额外重放两次，正文和签名头保持原样。SDK 重复计数增加 4，两个计数处理器仍各只执行一次。                                                                 |
| 处理中崩溃 | 私聊测试事件已返回 HTTP 200，处理器已开始、尚未完成时，对独立 SDK 服务发送 SIGKILL。约 2.95 秒内观察到 systemd 自动启动的新进程就绪；入口进程保持运行。                  |
| 重启后重放 | 在原签名有效期内，对同样两条事件各重放两次。新进程各接纳一次、识别一次重复；同一事件在两个进程中累计执行两次。                                                           |
| 恢复后收发 | 重启后私聊、群聊的新命令均回复成功，用户确认收到。                                                                                                                       |
| 收尾       | 两个临时服务均正常停止，SDK 队列、等待项和缓存归零，探针保留的正文及身份作用域清空，内部端口关闭，Nginx 超时恢复至原配置。                                               |

本轮 SDK 未上报非预期错误。进程被终止是主动注入的故障，不算作正常关闭；只对恢复后的新进程进行了有序关闭及资源检查。

## 已确认的边界

- 进程内去重有效；本轮同一事件在进程重启后再次进入处理器。不能用它代替跨重启的业务幂等。
- HTTP 200 表示已接纳，不表示处理器完成。本轮被终止的任务没有在新进程中自动恢复，后续观察期也未收到这条事件的再次投递。
- 需要保证业务结果的应用，应单独设计持久化接纳与幂等。本轮没有实现数据库、持久化队列或业务副作用。
- 重试和断开间隔只描述本次样本，不声明 QQ 平台固定的超时、次数或重试间隔。

## 证据范围

- 本机与服务器各通过 5 项离线探针检查；新应用实例测试不算作真实进程崩溃验收。
- 新代理链路通过 13 项公网合成协议检查；公网控制路径返回 404。
- HTTP 503 和延迟场景的第二次投递来自平台，用户每条只发送一次，没有主动重放。
- 去重与跨重启验证使用真实事件的**受控重放**，不标记为平台自动重投。原始正文只在服务内存中短暂保留，未写入记录。
- 仅覆盖本次机器人、一位私聊用户及一个群。未测试其他 HTTP 状态码、整机故障、入口进程崩溃、多日运行或 2,000 群容量。
- 文档和实现只用于提出假设，结论来自上述测试；本轮不以 QQ 官方 SDK 作为参考。
