# 并发对照与 CPU 定位（2026-10-20）

**提高并发有收益，但本轮六档都未达到稳定 500 次/秒。** 所有正式轮次的发压完整性通过、漏发为 0；末尾仍有接近 2,000 条积压。因此本轮不调整框架默认并发，也未继续尝试 1,000/s。

## 对照条件

- 发压端在本机，SDK 与模拟 API 在目标服务器；模拟 API 的固定延迟继续走服务器环回网络。
- 服务器为 2 vCPU / 约 1.92 GiB，SDK、API 夹具和监督进程合计限 1.5 核 / 1 GiB、无 swap；sshd 开销另计。
- 每轮 10 秒 200/s 预热、120 秒 500/s 测量、15 秒 200/s 恢复，随后排空和关闭；每轮重新创建实例。
- 单账号、2,000 个合成群标识，保留命令、权限、图片、DOCX、按钮、prompt 和预设错误；正式对照不注入大包或下游故障。
- 六档只有入站/出站并发不同，源码指纹和其他参数一致；发压上限固定为 128 条连接、2,048 个在途请求。
- 端到端耗时由发压端同一个单调时钟计算，包含 SSH 输入、排队及完成通知返回；服务器另记接纳后的耗时。

## 结果

| 入站/出站 | 接纳并完成的首次事件 | 接纳比例 |    成功 P95 / P99 | 末尾排队中位数 |
| --------- | -------------------: | -------: | ----------------: | -------------: |
| 32/8      |      33,144 / 60,000 |    55.2% | 19.626 / 20.646 s |          2,000 |
| 32/16     |      41,057 / 60,000 |    68.4% | 15.714 / 16.453 s |          2,000 |
| 64/16     |      48,492 / 60,000 |    80.8% | 13.057 / 15.149 s |          2,000 |
| 64/32     |      46,795 / 60,000 |    78.0% | 12.889 / 16.967 s |          1,999 |
| 128/32    |      55,044 / 60,000 |    91.7% | 10.011 / 14.560 s |          1,994 |
| 128/64    |      54,155 / 60,000 |    90.3% |  8.774 / 17.544 s |          1,975 |

- 接纳按唯一首次事件计数，包含经过模拟重试后取得 HTTP 200 的事件；不能据此声称首投均成功。HTTP 503、重复和重试统计见 [JSON](concurrency-review-2026-10-20.json)。
- 完成计数包含预设的权限拒绝、参数错误和业务异常；成功延迟仅统计成功业务。计数按原始阶段分组，可能在恢复或排空阶段完成，不能直接除以 120 秒当作稳定吞吐。
- `32/16` 减少了发送等待，`64/16` 又提高了处理量；继续增加出站并发没有带来稳定提升。`128/32` 是本轮接纳量最高的单次样本，不是已经证明的最优生产配置。
- SDK 测量阶段平均 CPU 约 0.94–1.13 核；发压端约 0.27–0.34 核。各档发压调度迟到 P99 均为 7 ms，未出现发压漏发。
- `128/64` 的发送端连接等待 P99 达到约 1.118 秒，所有延迟均计入结果。更高并发也会放大等待，不能只看执行名额。
- 各档仅运行一轮，没有置信区间。本轮测的是含验签的 Webhook 链路，不能据此断言 WS 的吞吐上限。

## CPU 证据

- 两轮独立诊断不纳入容量表。第一份采样跨到了恢复阶段，原文保留；第二份由程序定时触发，位于服务器开始后的 19.327–39.495 秒，完整落在 10–130 秒测量区间。
- 在目标 Node 24.21.0 上实测确认了 V8 Profiler 与 hrtime 的单调时钟 epoch 一致，并校验 inspector PID 确属本轮 SDK。
- 稳定段采样约 **39.29%** 落在同步 Webhook 验签调用链，垃圾回收约 **6.43%**；HTTP 与资源管理还有分散开销。调用链百分比包含子调用，不能相加。
- 这是过载并包含模拟重试时的单次采样，不代表所有负载的固定比例，也不是某项优化已经有效的证明。
- 后续应优先评估验签执行方式与 HTTP/资源分配成本，并独立补充 WS 基准。不能关闭验签或缩短去重、回复记录窗口来换取数字。

## 资源与收尾

- SDK 测量阶段最高采样 RSS 约 252 MiB；测试进程组最高约 334 MiB。主机可用内存始终高于约 1,030 MiB，无 OOM 或内存保护停止。
- 各测试组有 CPU 配额限流，约 5.0%–13.1% 的采样调度周期被限流；因此不是 SDK 独占两核的容量结论。PostgreSQL 仅观察资源，未承接测试 SQL。
- 六轮 SDK、夹具与发压端资源检查全部归零；比较单元、监控单元和 inspector 已结束，SSH 转发关闭。
- Nginx 主进程仍为原 PID 989；PostgreSQL 未重启、无 OOM，就绪检查通过。真实 QQ、SQL、图片渲染及多日运行仍需分别验收。
