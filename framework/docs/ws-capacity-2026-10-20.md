# WS 容量与隔离验收（2026-10-20）

**单账号 WS 在本次配额与模拟负载下，最高重复通过 500 次/秒。** 具体时长、失败和观测开销见下表；这不是 QQ 平台配额或真实业务容量承诺。

500～750 次/秒之间尚未定位精确边界。本轮 Webhook 500/s 单轮通过，与[此前的波动结果](bottleneck-review-2026-10-20.md)并存，不能用这一轮覆盖旧失败。

## 范围

- 目标服务器上 SDK、模拟 HTTP API 和监督器共享 1.5 核 / 1 GiB，测试组禁用 swap；入站/出站并发为 128/32。发压端与 WS 网关位于本机，经 SSH 连接，网关不占服务器配额。
- 同一 SDK 源码、工具与混合业务，2,000 个合成群槽位。双账号共享入站/出站预算，使用各自的群 OpenID；账号内缓存仍遵循原有预算。
- 每轮 10 秒 200/s 预热、指定负载、15 秒 200/s 恢复，随后排空。500/s 测量 5 分钟；750/s 测量 4 分钟，以保持单轮首次事件不超过 200,000。
- 使用内存持久化测试端口，未加载真实 QQ 凭证或 SQL；Nginx/TLS、图片渲染、平台配额与多日生产稳定性均未纳入。
- 表中计数是首次事件，包含预设的权限拒绝、参数错误与业务异常，不能当作发送消息数。P95 是成功业务的端到端耗时，包含 SSH 和完成通知；部分任务在恢复段完成，不能直接用队列排空后的总数计算稳态吞吐。

## 阶段观测

- 单账号 WS 500/s：关闭观测的两轮 SDK 平均 CPU 约 0.869 / 0.867 核，开启指标的一轮约 0.996 核；P95 为 584 / 577 / 654 ms。这是有限样本中的约 15% CPU 差异，不是固定开销保证。观测默认仍关闭。
- 500/s 指标轮无测量、采样或时间窗口丢弃。按不跨阶段的 5 秒窗口聚合：WS 解析约 0.014 ms，接纳约 0.041 ms，文字绑定约 0.012 ms，入站排队约 1.28 ms，出站排队约 7.75 ms，QQ HTTP 约 31.30 ms，上下文加载约 63.78 ms。
- 以上是每个已完成操作的平均墙钟耗时，阶段之间可能嵌套或并行，不能相加为 CPU 成本；上下文加载包含夹具预设延迟。后续应先分析共享 HTTP/出站和对象分配，再用单变量对照验证优化。

## 工具修正与失败保留

- 初次本地 WS 冒烟错误地读取 Webhook handler，启动失败；修正后本机和服务器协议冒烟通过，原失败保留。
- 第一版正式 WS 400/s 全部 120,000 条完成，但两次预设业务异常的 onError 晚于事件完成，旧工具因临时条目已释放而误判未知失败。这轮完整性失败保留，没有改成通过。
- v2 在内部错误上报入口同步计数，保留真实日志、脱敏和异步 onError 行为；晚到回调另计数。强制延迟回调回归通过，正式表全部使用 v2 工具。SDK 运行时未变。
