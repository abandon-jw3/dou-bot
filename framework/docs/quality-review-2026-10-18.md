# 框架质量审查（2026-10-18）

对象：主工作树 `main / 07d2c3e` 上尚未提交的多机器人源码。审查围绕性能、易用性、可维护性；源码契约仍为 **2.0**，版本仍为 **0.8.0**，没有新增依赖、发布、部署或真实 QQ 联调。

## 结论

- **性能**：共享有界队列、按账号轮转和懒加载方向保留。本轮主要减少图片重复复制、上下文客户端分配和队列扫描；合成吞吐变化较小，不能宣称显著提速。
- **易用性**：优先修复“正常调用却失败”和“错误配置被忽略”。默认按钮确认、缓存客户端、账号恢复和配置错误反馈已补齐。
- **可维护性**：应用生命周期、账号管理、后台发送分开；显式客户端转发代替反射 Proxy；配置校验共用小模块。保留参数、Guard、prompt 和上下文现有语义。
- 当前最需要后续证据的是多账号真实 QQ、长时间运行和实际发行候选的跨平台 CI。短时离线通过不能替代这些验收。

## 范围

- 源码审查覆盖应用/账号生命周期、DI 与装饰器、路由/参数/权限/冷却、上下文/会话、入站/出站预算、QQ API/Token、WS/Webhook、消息编码、PostgreSQL、公开契约与测试入口。
- 本轮修改 20 个源码文件，其中新增 4 个内部模块；没有扩大公开 API。详见 [机器可读记录](quality-review-2026-10-18.json)。
- 对确认的缺陷先构造失败用例，再修复；新增 14 项行为回归。已有未提交重构和 Webhook 修复保留。
- 示例项目、文档站与技能继续使用 npm 0.8.0，不提前接入新源码。

## 已复现并修复

| 问题                                        | 影响                                                 | 处理                                         |
| ------------------------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| API 转发省略 ACK code 时把 options 放错位置 | `acknowledgeInteraction(id)` 失败                    | 显式方法签名，保留 `code = 0`                |
| 缓存客户端/API 绑定旧运行时                 | 停止并恢复机器人后，旧引用不能发送                   | 后台客户端在调用时解析同账号当前运行时       |
| 启动失败后的重试与旧清理重叠                | 旧清理可能取消新一轮任务                             | 合并并发启动，先等待旧清理完成               |
| WS 恢复只检查本账号容量                     | 其他账号占满共享预算时仍提前恢复                     | 同时订阅本地和共享容量变化                   |
| 后台 ACK 刷新 Token 与关闭竞态              | 已接纳确认被提前结束；共用 signal 的操作互相移除登记 | 独立有界控制通道，逐操作信号及完整排空       |
| Module/Command 字段拼错被忽略               | 配置没有生效也没有提示                               | 拒绝未知字段与非法数组                       |
| Provider 字段拼错或 inject 非数组           | 丢失依赖或出现缺少分类的原生错误                     | 拒绝未知配方字段，统一报 DEPENDENCY          |
| Provider 配方未形成配置快照                 | 外部修改 inject 或 factory 后改变启动结果            | 声明时复制冻结配方与数组，保留 useValue 身份 |
| PostgreSQL 连接失败被归类为结构错误         | 误导使用者重复运行迁移                               | 区分 DATABASE 与 DATABASE_SCHEMA             |
| 数据库握手阶段的连接未纳入强制收尾          | 关闭超时后仍留下连接                                 | 从创建 socket 起跟踪，截止时间后断开         |

配置快照、默认参数、账号恢复、关闭期间 Token 刷新、跨账号背压均有离线回归。数据库断连和握手超时使用真实本地 TCP；数据库迁移、选路、事务与连接归还使用专用 PostgreSQL 的随机 schema。

## 性能处理与实测

- 图片在业务调用时取得一次字节快照，排队、上传与发送复用快照；业务修改原数组不会改变已排队内容。
- `ctx.client` 按需创建；`ctx.target` 仍是可序列化的冻结地址。
- 出站等待队列改为链表；等待项取消不扫描数组、不移动剩余元素；按账号统计排空状态。3,000 条等待消息的交错取消与跨账号推进回归通过。
- 默认未启用的 debug 日志不遍历字段；每条有效日志只获取一次脱敏值列表，补充 password 与 Error.name 脱敏。
- API facade 用 `satisfies QQApi/QQClient` 检查方法完整性，避免新增方法遗漏转发。

复验：`npm run benchmark:framework -- 5 <label>`。前后完整样本保存在本记录 JSON 中。

## 仍需明确的生产边界

- **消息交付**：PostgreSQL 当前保存地址和选路，不保存消息任务。HTTP 已确认但业务尚未完成时崩溃，任务不会自动恢复；跨进程去重也未提供。
- **账号公平性**：轮转保证已接纳任务的执行顺序；共享预算不预留每个账号的独立接纳份额。是否增加每账号配额，应依据实际突发负载决定。
- **容量**：历史缓存、Token 与连接按账号累加。2,000 群模拟不是 2,000 机器人测试，也不代表 QQ 发送配额。
- **发布验证**：需要当前源码的真实双机器人收发/恢复、较长模拟与业务观察，以及提交后的跨平台 CI；已有单机器人 0.8.0 记录不能替代。

本轮原始失败日志、源码快照和安装包位于被 Git 忽略的 `framework/work/quality-review/` 与 `framework/work/package-check/`；跨设备时需另行携带。历史验收 JSON 和指纹保持原样。
