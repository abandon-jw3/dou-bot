## 建连错误的证据

当前源码按原 256 条 HTTP 连接配置跑完整 350 秒，复现 **23 次 connect ECONNRESET**：1 次在 1,000/s 阶段、22 次在 2,500/s 突发阶段；SDK 内部非预期错误为 0。

为排除业务和签名逻辑，另用原生 Node TCP 服务做对照：只让独立服务子进程暂停接纳 250 ms，不使用框架、不更改系统设置。

| listen backlog | 同时建连 | 成功 | connect ECONNRESET |
| -------------: | -------: | ---: | -----------------: |
|            511 |       64 |   64 |                  0 |
|            511 |      256 |  128 |                128 |
|              8 |      256 |    8 |                248 |

本机 `kern.ipc.somaxconn=128`。这些实测说明，本机监听队列受压时能产生相同的建连错误。结合完整负载的错误阶段和下方对照，证据指向新连接突发超过本机接纳能力；没有据此修改 SDK 协议代码，也不能把结论直接外推到 Linux/Nginx 或 QQ 平台。

## 保持事件速率的完整复测

将压测客户端 HTTP 连接上限设为 64，保留全部阶段、事件速率、重试次数和在途请求上限。两轮 SDK 源码指纹一致。

| 指标               | 原 256 连接 | 64 连接复测 |
| ------------------ | ----------: | ----------: |
| 计划首次事件       |     149,750 |     149,750 |
| 压测端丢弃计划流量 |           0 |           0 |
| 连接错误           |          23 |           0 |
| SDK 非预期错误     |           0 |           0 |
| 完整性判定         |        失败 |        通过 |

- 64 连接限制将部分等待移入客户端：最高采样排队 390 个请求；2,500/s 阶段分配连接等待 P99 为 18 ms，到达调度迟到 P99 为 7 ms。等待已计入确认延迟，未隐去流量。
- 共取得 395,703 个 HTTP 响应，其中 110,849 个 200、284,854 个 503；包括模拟重试和对话。过载拒绝不算成功业务吞吐。
- 50/s、200/s 阶段首次事件全部得到接纳；500/s 阶段出现持续积压和拒绝，不能称为稳定承载 500/s。
- 出站队列本轮使用新框架默认并发 8，入站使用 32；旧报告没有独立出站限制。因此不能直接拿两版业务吞吐作同配置性能结论。
- 关闭后队列、任务、缓存、会话、信号和定时器归零。实际 QQ 配额、部署服务器容量和多日稳定性仍需独立验证。

本次是单机、单轮配对实验，无统计置信区间；64 是本轮已验证配置，不是所有环境的最佳值。

## 压测工具修正

- 增加有界连接诊断：错误阶段、系统调用、是否复用、是否建连、读写字节、连接等待与服务端关闭计数。
- 增加出站队列采样，明确共享预算带来的等待。
- 增加 70 秒 connections 配置，便于复验建连和关闭场景；保留原 smoke/standard 配置。
- 增加 DOU_BOT_BENCHMARK_MAX_SOCKETS。仅改变 HTTP 连接上限，不改变计划事件速率；非法值直接拒绝。
- 关闭实验先等全部注入请求取得 HTTP 确认，再关闭 SDK。之前曾在 shutdown 阶段产生 4 次由实验提前关机造成的 reset/refused；同一 256 连接短流程补验后为 0。
- 追加多账号回归：慢选路占用出站预算、满额拒绝、429/503 不触发跨账号发送，失败后的后续请求仍能完成。

本机复验命令（在 framework 执行，报告标签不能复用）：

```sh
npm run benchmark:mixed -- connections local-connections
DOU_BOT_BENCHMARK_MAX_SOCKETS=64 npm run benchmark:mixed -- standard local-standard-64
```

PowerShell 先设置同名环境变量再运行命令，结束后移除该临时设置。默认仍为 standard 256 / smoke 128 条连接，便于与原记录对照；报告保存实际配置。
