# 目标服务器容量与稳定性验收（2026-10-20）

**65 分钟持续测试通过；完整阶梯负载未通过。** 50/s、200/s 短时阶段无积压，高负载阶段压测端漏发，不能据此确定稳定吞吐上限。两项结果分别保留。

## 环境与测试边界

- 服务器：2 vCPU、约 1.92 GiB RAM，Intel Xeon Platinum 8255C，Debian 12，Node 24.21.0。
- 来源：干净检出的 main / f8dde93；SDK、压测工具指纹见 [JSON](server-capacity-2026-10-20.json)。
- 两项容量测试均为单账号合成负载；真实双账号功能验收另见 [双 WS 实测](live-multi-bot-2026-10-20.md)。
- 测试进程组共享 1.5 核 CPU、1 GiB 内存，不允许使用 swap；SDK、发送端和下游夹具都计入此预算。
- PostgreSQL 与 Nginx 同机运行，未修改其配置和数据。数据库仅采集资源指标，未承接压测 SQL。
- 测试在独立网络命名空间运行，不连接真实 QQ；未覆盖真实数据库查询、Nginx/TLS 或浏览器图片渲染。
- 主机每 5 秒采样；连续三次可用内存低于 192 MiB 时，观察器只停止本轮测试。两项测试均未触发该保护。

## 短时容量结果

冒烟测试通过。完整阶梯负载运行 350 秒，计划 149,750 条首次事件，覆盖 2,000 个群标识；使用 64 条发送端 HTTP 连接。

| 阶段         | 首次事件 HTTP 200 / 计划 | 所有尝试漏发 | 最高采样排队 |     成功 P95 / P99 |
| ------------ | -----------------------: | -----------: | -----------: | -----------------: |
| 50/s，60 秒  |            3,000 / 3,000 |            0 |            0 |     474 / 1,537 ms |
| 200/s，45 秒 |            9,000 / 9,000 |            0 |            0 |     482 / 1,539 ms |
| 500/s，45 秒 |          14,613 / 22,500 |          184 |        2,003 | 19,228 / 38,548 ms |

- 混合业务包含等待 1.5 秒的 prompt；P99 不是纯文字指令耗时。200/s 只验证了该短时阶段，不是长期生产容量保证。
- 500/s 起持续积压；更高负载和大消息阶段也有漏发。全轮共漏发 70,934 次尝试，其中首次事件 41,725 次，其余包括重试、重复投递及对话。
- 发送端与 SDK 共用 CPU，约 29.1% 的 cgroup 调度周期触发限流；高阶段无法区分 SDK 上限与压测端资源不足，需要独立压测端后再测。
- SDK 与发送端非预期错误为 0，连接错误为 0；HTTP 503 拒绝不算成功业务吞吐。完整性检查因漏发退出 1，失败原文保留。
- 降回 50/s 后，约 22.6 秒观察到队列归零并保持；计时精度约 1 秒。关闭实验按预期触发 SHUTDOWN_TIMEOUT，约 908 ms 返回，队列、任务、缓存、会话、信号和定时器均归零。

## 短时容量阶段的资源表现

- SDK 最高采样 RSS 361.0 MiB；整个测试进程组最高约 737.3 MiB，未发生 OOM。
- 主机最低可用内存约 693.8 MiB；全机 swap 使用由 56.0 MiB 增至最高 133.3 MiB。测试进程禁止使用 swap，不代表其他进程没有换页。
- PostgreSQL cgroup 最高约 60.2 MiB，未出现 OOM；压测后就绪检查通过，Nginx 保持 active。这不是数据库吞吐测试。

## 65 分钟持续测试

- 北京时间 01:42:57 启动、02:47:59 正常退出；实际负载与排空耗时 **3,901,155 ms（约 65 分 1.2 秒）**，退出码 0。
- 常态 20/s，每十分钟增加一次 30 秒的 50/s 高峰；覆盖 2,000 群标识，共 84,300 条首次事件，全部完成加载并进入处理器及发送路径。
- 3,372 次重复投递被去重；拒绝为 0，64 个分钟采样点的排队数均为 0；单次排队耗时最高约 8.0 ms。
- 每第 997 次发送故意返回 503，共 84 次，最终失败计数恰为 84；非预期失败为 0。故意失败不记成成功发送。
- 80,083 条事件在 250 ms 内完成，另 2 条在 500 ms 内完成；4,215 条预设慢处理事件落入 2.5 秒桶。全程最长约 2,202 ms，发送调度迟到最高约 16.7 ms。
- 关闭后队列、保留字节、去重、回复范围、任务、信号、定时器、prompt 和冷却记录全部归零。

- 一小时后回复记录维持约 77,400 条，符合当前保留窗口；结束前去重记录约 12,900 条，未触及上限。完整分钟序列保存在 JSON。
