## 保留并纳入兼容检查的行为

| 范围      | 1.0 候选契约                                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 公开入口  | dou-bot 与 dou-bot/testing，ESM、传统 TypeScript 装饰器。RuntimePorts、Clock、Container、Execution 及深层路径不是业务 API                                          |
| 模块与 DI | 模块 imports/exports 决定可见性；Provider 默认单例；Controller 不作为共享 Provider；接口令牌用 Inject；useValue 的外部资源由调用者管理                             |
| 参数      | 默认前缀 /，空前缀替换默认值；Option → Arg → Slot → Rest；匹配器同步无副作用；Rest 不掩盖歧义或缺参；旧 Arg 的字符串和默认参数行为保留                             |
| Guard     | 模块 → 类 → 方法；拒绝后不解析参数、不占冷却。模块只覆盖自己的 controllers；不传播到 imports，不保护原始 On 观察器，不自动过滤 HelpModule 列表                     |
| 冷却      | Guard 和参数通过后占用；别名共享；业务失败不返还；user 范围为同一会话中的用户；它不承担业务互斥锁的作用                                                            |
| prompt    | 按应用、场景、会话和用户隔离；回答属于父流程，不重新执行命令、Guard 或冷却；后续回复引用新消息；业务必须 await                                                     |
| 生命周期  | 框架 QQ 接入由 start 启动；关闭后不能重启同一实例；关闭取消未完成的 prompt，异步业务需配合 signal；同一 close 结果共享                                             |
| 错误      | Guard 正常拒绝不是错误；PARAMETER_PARSE、QQ_API 等按阶段上报。业务 catch 了受管操作的失败，也不取消其 onError 记录；错误码和阶段用于判断，提示字符串不作为稳定协议 |
| 状态      | snapshot 返回运行状态和计数快照；accepted 表示接纳，不代表业务或发送成功。进程内去重和队列不提供跨重启恰好一次保证                                                 |

重点默认值保留：commands.prefix 为 `/`，invalidInput 为 `report`，按钮确认模式为 `auto`，并发为 8，关闭总期限为 10000ms；prompt 默认等待 60000ms、最长 300000ms、最多 1000 个等待项、取消词为“取消”。改变这些行为应作为兼容性变更审查，不能只通过类型检查就认定兼容。

## testing 入口的具体契约

声明见 [testing-api.d.ts](testing-api.d.ts)。

- enqueue 立即返回接纳结果；accepted/duplicate 带 done，ignored/overloaded/stopping/failed 不带 done。duplicate 共享原流程的完成 Promise。
- done 及 dispatch 等待框架处理完成，业务失败通过 errors/onError 观察；不能把完成 Promise 当成业务成功结果。
- prompt 回答的 done 可能与父流程一起完成。多轮测试应观察下一条问题，再投递下一条回答，不能等待第一条回答 done 后才推进第二轮。
- flush 等待所有在途工作；未回答的 prompt 也在其中。需要驱动输入、超时或关闭，不能用 flush 代替这些动作。
- 默认 messages、acknowledgments、errors 是测试记录；respond 覆盖的 HTTP 响应不进入默认发送记录。这些数组不适合作为长跑日志容器，因此持续运行工具使用计数和每轮清空的有限捕获。

## 持续运行工具

入口为 examples/soak.ts；组合工作负载在 examples/soak-controls.ts，资源诊断和中断处理在 examples/soak-support.ts。这里的私有计数读取仅服务于框架自身验收，不扩展 SDK 的公开 API。

每轮在群聊和私聊中验证三级 Guard 拒绝、参数错误后的有效查询、无序 Slot/Rest/Option、别名冷却和重复投递。随后并发驱动多轮输入、取消、超时和问题发送失败；命令形状的回答不得重新进入路由。结束时保留两条未回答的 prompt，再关闭应用，核对取消、错误分类以及全部受管资源归零。

已有文本、图片、Markdown、按钮、短 TTL、token 刷新、过载和 QQ 接口故障注入继续保留。自动回归另以 concurrency=1 验证多条 prompt 可以推进，并用故意损坏的响应确认工作负载会失败。

```sh
npm run test:api
npm run check
npm run test:compat
npm run soak -- 180000
```

test:compat 需要先完成 build/check；它从官方 registry 安装精确的 0.6.0，验证历史消费者。普通 test:package 则安装当前源码产生的 tarball，验证同一消费者和新增 TestAdmission 声明。

soak 时长允许 30000～259200000ms（30 秒～72 小时），默认三分钟。例如 `npm run soak -- 259200000` 启动本地 72 小时模拟运行。CI 在 Windows/Linux 执行 30 秒组合回归，保存两平台 JSON 报告为 artifact，保留 14 天。本次没有启动 72 小时任务，也没有连接真实 QQ。

每次报告保存在 work/soak-随机ID.json，并更新 work/soak-latest.json。报告记录实际时长、Node/系统、源码提交、工作区是否有改动，以及 src/**/*.ts 和三个 soak 源文件按路径排序的 SHA-256 指纹。文件版本不能只看 package.json 的 0.6.0 判断。

采样使用主动 GC，最多保留最近 240 个点；累计采样数和被丢弃点数另行记录。heapUsed、RSS 是采样值，不能当成完整峰值或凭短时结果证明长期无泄漏。事件 failed 包含有意触发的参数、发送及关闭取消错误，另用 unexpectedErrors 区分异常失败。

本次三分钟结果见 [持续运行记录](soak-validation-1.0-review.json)，原 0.1.1 基线继续保留在 [历史记录](soak-validation.json)。两者的工作负载不同，不直接比较吞吐高低。
