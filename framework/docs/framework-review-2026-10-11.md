## 结构和高频路径调整

- 将每次调用的 Context、发送记账和取消管理移入 [event-task.ts](../src/core/event-task.ts)，[execution.ts](../src/core/execution.ts)保留接纳、队列、去重和会话调度。启动校验统一命名为 validateControls，涵盖 Guard 和中间件。
- 启动时编译参数类别、身份和上下文注入索引；不再在每次调用时重复筛选全部声明。choices 保留原数组供帮助展示，同时建立集合用于匹配，减少大枚举的线性查找。
- 没有 Ctx 参数时不创建处理器 Context；上下文 reader 保持稳定且只读，实际存储按需创建。同步 prepare 在不读取 signal 时不分配取消控制器，也不安排没有必要的计时器。
- 图片上传使用已经取得的 SDK 快照及 Buffer 视图，减少重复的字节复制，保留入口快照、大小限制和取消行为。
- 附件接纳只判断是否存在匹配项，不创建完整筛选数组；实际调用时仍按顺序产生独立的冻结数组。
- 去重淘汰不再将整个 Map 展开成数组。记录最近到期时间，缓存未到期时直接跳过全量清扫，降低满容量拒绝路径的 CPU 开销。

Provider 默认单例、模块可见性、参数消费顺序、Guard/冷却、按钮确认、prompt 所有权和附件顺序执行均保持原约定。没有加入数据库、业务默认值装饰器或运行依赖；TypeScript 仍为 5.9.3。

## 性能对照

使用同一主机、Node 24.21.0 和完全相同的编译后测量程序。修改前后各独立运行两次，每次五轮，以下为合并十轮的中位数。完整样本与测量程序 SHA256 见 JSON 记录。

| 场景                       | 修改前每秒处理数 | 修改后每秒处理数 |            变化 |
| -------------------------- | ---------------: | ---------------: | --------------: |
| 无参数命令                 |          126,343 |          138,471 |           +9.6% |
| 文本回复                   |           43,372 |           43,728 | +0.8%，近似持平 |
| Slot/Option/Rest 与归一化  |          103,105 |          117,686 |          +14.1% |
| 513 项枚举匹配             |          107,812 |          121,819 |          +13.0% |
| 中间件懒加载与两次参数读取 |           63,242 |           62,361 | -1.4%，近似持平 |
| 注册但不读取上下文数据     |           85,070 |           93,531 |           +9.9% |
| 64 KiB 图片上传及发送      |            6,464 |            7,982 |          +23.5% |
| 回复缓存已满时的正确拒绝   |           14,488 |          685,921 |      约 47.3 倍 |

这些是合成事件和内存 HTTP 响应的测量，不代表 QQ 服务端或公网吞吐。最后一行测量的是过载拒绝能力，不是业务接纳量。小于 5% 的变化记为近似持平，本次样本不足以证明稳定收益或退化。RSS 是采样值，不能当作实际峰值或 SDK 净占用。

复测当前源码：

```sh
npm run benchmark:framework -- 5 local
```

结果写入 `work/benchmark-framework-local.json`。比较改动时应使用相同程序、Node、主机和容量配置，并保留预热及多轮样本，避免只比较一次最快结果。

## 验证结果与边界

- Node 24.0.0、24.21.0 各 287 项 SDK 测试通过，包含本地 WS/Webhook 协议对照；148 个导出、108 组双向类型检查通过。
- 当前 tarball 的历史和新增消费者，以及 registry 上的 0.6.0、0.7.0 消费者均通过；发包白名单和凭证扫描通过。
- 覆盖率：行/语句 98.86%、函数 98.25%、分支 91.02%。覆盖率变化受代码拆分影响，不能单独作为正确性结论。
- 业务示例完整检查通过：36 项业务测试和 7 项开发进程测试；后者按已确认的沙箱限制，在获准环境中执行。文档站 18 项测试与 39 页静态构建通过。业务示例、网站和技能的运行代码及 npm 0.7.0 依赖未修改。
- SDK 生产依赖审计为 0 项漏洞。
- Node 24.21.0 三分钟持续运行通过，实际 180040ms，共接纳 288092 个事件；其中 204864 条批量业务消息各加载一次上下文数据。预期外错误为 0，238 次故意注入的 QQ 接口失败全部被记录；统计中的 failed 还包含故意制造的参数和 prompt 错误。
- Node 24.0.0 另完成 30 秒同工作负载检查，接纳 45812 个事件，预期外错误为 0，关闭后全部受管资源归零；原始报告已并入 JSON 记录。
- 关闭后 pending、active、retainedBytes、dedup、replyScopes、tasks、signals、timers、prompts、cooldowns 全部为 0。独立的 1000 条消息强制 GC 探针显示，应用尚未关闭且保留去重/回复缓存时，已完成 EventTask 的存活弱引用数已为 0。
- 三分钟堆采样上界约 14.6 MiB，RSS 采样上界约 246.1 MiB，包含 Node、原生 Response 和缓存的开销。采样存在增长，短时检查及对象回收探针不能证明多日运行无泄漏。
