# 阶段性能观测与开销验证（2026-10-20）

**首版已实现，默认关闭。** 可分辨入站排队、回调执行、回复串行等待、出站排队和 HTTP 等阶段；不新增生产依赖。使用方法见 [阶段性能观测](diagnostics.md)。源码契约仍为未发布的 2.0，SDK 版本保持 0.8.0。

## 实现边界

- 独立的 `app.diagnostics.snapshot()` 提供累计分桶指标、结果计数、在途数量和最老任务年龄；普通容量快照保持原用途。
- `traceSampleRate` 在入口或后台操作上采样，内部显式传递关联信息，框架自有信号由应用级 WeakMap 关联；没有全局上下文。
- 使用固定阶段、配置账号、注册处理器和固定 API 类别，不保存正文、QQ 用户/群/消息 ID、URL、SQL 或异常文本。
- 指标、在途观测和采样缓冲均有上限；超限记录丢弃，不拒绝业务。缓冲包含仍由慢导出器持有的批次。
- `onSpans` 在请求路径外批量执行。失败/超时停用自动导出并计数，不调用业务 onError；仍在同一进程，导出器自身应避免同步阻塞。
- 时间是单调墙钟时间。嵌套和并行不能相加，也不能替代 CPU profile。数据库只记录框架路由操作总时间；任意业务 SQL、fetch 和渲染未自动细分。

## 计时与生命周期回归

- 覆盖分桶边界、活动年龄、采样继承、隐私、三类资源上限、导出异常/超时/非法返回、迟到结果及关闭。
- 验签超时后，`webhook.verify.wait` 已结束，`webhook.verify` 继续保持在途直到原生回调；测试没有把取消等待当作原生工作完成。
- 使用可控时钟确认回复串行等待位于出站队列之前，prompt 挂起与执行时间分开，输入错误提示回复包含在 handler.total 内。
- 跨账号发送保持源执行关联，HTTP 指标归属实际发送账号；尚未确定发送账号的路由等待不填写 appId。
- 关闭后单独保留读取器曾使应用无法回收；WeakRef 实测复现后，已改为独立关闭状态并释放用户导出回调。两种模式的 GC 回归在本机两版 Node 和服务器 Linux 上通过。

## 服务器开销对照

- 同一 2 vCPU / 约 1.92 GiB 服务器，测试组固定 1.5 核 / 1 GiB，无 swap；SDK、模拟 API 和监督进程共享预算，SSH 另计。
- 固定 300/s、执行/出站 128/32，每轮测量 60 秒，前后分别 10 秒 200/s 预热和 15 秒 200/s 恢复。
- 三种模式各两轮，第二轮逆序；工作负载与源码指纹一致。sampled 为 1%，导出器仅计数并保留最多 80 条示例。
- 六轮各 18,000 条首次事件全部接纳并完成，发压漏发、尾队列中位数、诊断丢弃及导出失败均为 0；所有退出和释放检查通过。

| 模式    | 两轮成功回复 P95 | SDK 平均 CPU | 相对关闭模式 |
| ------- | ---------------- | ------------ | ------------ |
| off     | 553 / 552 ms     | 0.770 核     | 基线         |
| metrics | 560 / 560 ms     | 0.840 核     | +9.1%        |
| sampled | 558 / 556 ms     | 0.823 核     | +6.9%        |

- 开启细分观测有可测 CPU 成本。本轮低于饱和点的延迟相近，不能据此证明极限吞吐不变。
- 每种模式仅两轮，metrics 与 sampled 的小差异处于运行波动范围；不能解释为采样比纯指标更省 CPU。
- 该矩阵运行在引用修正前的冻结版本。修正只处理初始化/关闭引用与导出回调释放，阶段与工作负载未改；最终版本另通过三档服务器冒烟。两份源码指纹和原始结果分别保留，未将旧结果改标为最终源码。

## 最终版本微基准

- 独立进程、三轮交错顺序，每例预热 5,000 次、测量 10,000 次带 Slot 与模拟回复的指令。
- 改动前关闭模式耗时中位数 223.070 ms，最终关闭模式 225.062 ms，差约 0.9%；不是零成本保证。
- 指标与 1% 采样分别为 324.932 / 334.309 ms，约增加 10–11 微秒/轻量指令。这个纯内存测试不能外推到 Webhook 容量。
- 最初同进程探索存在模式混跑和 JIT 干扰，后续独立进程结果单列；两者均保留。
