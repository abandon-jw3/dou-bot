# 用 dou-bot 开发 QQ 机器人

帮助使用者在自己的应用中编写机器人业务，沿用已有模块、权限和命令习惯。

示例适用 **dou-bot 1.0.0-rc.1**（候选试用版）。已有项目以锁文件和已安装包的类型声明为准，按任务需要选择 API；升级依赖应属于用户要求的范围。

## 开始工作

1. 找到应用的 `package.json`、锁文件、入口和模块，确认实际使用的 dou-bot 版本。
2. 按用户的输入方式、期望回复和目标账号选择功能；在应用目录修改业务代码。
3. 业务从 `dou-bot` 导入，测试从 `dou-bot/testing` 导入。技能可单独复制使用，无需框架源码仓库。
4. 运行应用已有的构建与相关测试；真实 QQ、数据库和外部服务联调按本次任务范围执行。

## 编写业务时

- 用传统装饰器和构造元数据；注入类保留值导入。新项目的编译配置见项目指南。
- Provider 在多个账号和请求之间共享；当前账号、用户、群和 Context 通过方法参数传递。
- 命令回复用返回值或 `ctx.reply()`；后台通知保存完整 `ctx.target`，通过 `MessageSender` 发送。
- 同一真实群在不同机器人下的 OpenID 不能互换；业务记录按账号、场景和 OpenID 区分。
- PostgreSQL 为必需配置，首次显式迁移；业务表和任务持久化由应用管理。
- `Slot.match/normalize` 只做同步转换；异步查询放 Service 或 `prepare/provide`。
- 异步工作明确等待并传递取消信号；外部 WS/定时器在应用就绪后启动、停止时清理。
- Context 只用于本次处理；后台任务保存业务数据，不保存旧 Context。
